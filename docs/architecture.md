# System Architecture — PromptPolish

PromptPolish is structured as a lightweight Next.js App Router application integrated with Supabase Postgres and Vercel AI SDK. This document details the application routes, execution pipeline, data models, and access-control boundaries.

---

## 1. Directory & Routing Architecture

```text
app/
├── (landing)/
│   └── page.tsx              # Landing marketing page (localized in PL/EN)
├── analyze/
│   └── page.tsx              # Prompt submission and preflight form
├── result/
│   └── [id]/
│       └── page.tsx          # Private result view; reads owner cookie server-side
├── share/
│   └── [token]/
│       └── page.tsx          # Publicly shared view (if enabled; resolves by token)
├── api/
│   ├── analyze/
│   │   └── route.ts          # Pipeline orchestrator (limits, safety, AI output, save)
│   ├── feedback/
│   │   └── route.ts          # Saves upvotes/downvotes linked to analysis ID
│   ├── events/
│   │   └── route.ts          # Saves telemetry events (e.g., prompt copy triggers)
│   └── share/
│       └── route.ts          # Toggles public sharing of prompt results
├── privacy/
│   └── page.tsx              # Draft Privacy Policy
└── terms/
    └── page.tsx              # Draft Terms of Service
```

## 2. Core Execution Pipeline

For every prompt submission, the backend orchestrates a strict multi-layer pipeline:

```text
1. Client-Side Preflight
   └── Simple regex/entropy checks warn the user locally of high-risk sensitive data patterns.

2. Zod Schema Verification
   └── Parses text lengths, chosen language, profile slug, and custom formatting constraints.

3. Rate Limiting Check
   └── Resolves client IP hash and Cookie UUID. Verifies daily quota remains (< 5 / day).

4. Severe Sensitive Data Filter
   └── Scans for API keys, passwords, and tokens. Blocks process if high-risk data is detected.

5. Load Model Profile
   └── Queries the local static seed or `model_profiles` database for credentials and active model_ids.

6. Prompts Construction
   └── Assembles system guidelines and user criteria templates matching the chosen target profile.

7. Structured AI Generation
   └── Invokes Vercel AI SDK generateText with Output.object to fetch criteria scores & critiques.

8. Semantic Score Calculation
   └── The backend recalculates and weights scores mathematically to verify strict bounds.

9. Save to Database
   └── Inserts into prompt_analyses, linking it to the owner_anonymous_id resolved from the cookie.

10. Return Typed Payload
    └── Sends back formatted JSON representing the computed audit and refined prompt.
```

## 3. Database Schema Design (Supabase Postgres)

The application utilizes three main relational tables:

### 3.1 `prompt_analyses`

Holds records of prompt audits, scores, and improved outputs.

- `id`: `uuid` (Primary Key, default: `gen_random_uuid()`)
- `owner_anonymous_id`: `uuid` (Anonymous owner key, stored in user's secure httpOnly cookie)
- `input_prompt`: `text` (The original prompt pasted by the user)
- `improved_prompt`: `text` (The refined, optimized prompt generated by the model)
- `language`: `string` (`"pl"` or `"en"`)
- `profile_slug`: `string` (`"general-llm"`)
- `criteria_scores`: `jsonb` (Specific vector scores like context, format, role, constraints)
- `final_score`: `integer` (Calculated final rating, bounded 0–100)
- `weaknesses`: `jsonb` (Array of objects detailing specific weaknesses and severity)
- `explanations`: `jsonb` (Array of string descriptions explaining specific changes made)
- `is_share_enabled`: `boolean` (Default: `false`)
- `share_token`: `string` (Random high-entropy token generated for public opt-in view)
- `created_at`: `timestamptz` (Default: `now()`)

### 3.2 `usage_events`

Tracks application telemetry, anonymous limits, and usage patterns.

- `id`: `bigint` (Primary Key, Auto-incrementing)
- `ip_hash`: `string` (SHA-256 hash of user's IP for rate-limiting calculations)
- `cookie_id`: `uuid` (Session UUID resolved from client cookie)
- `event_type`: `string` (`"analyze"` | `"copy"` | `"feedback"`)
- `target_id`: `uuid` (Foreign key pointing to `prompt_analyses.id`, nullable)
- `metadata`: `jsonb` (Stores telemetry markers, e.g., upvote/downvote binary)
- `created_at`: `timestamptz` (Default: `now()`)

### 3.3 `model_profiles`

Maintains records of active model ids, verification tags, and stale parameters.

- `slug`: `string` (Primary Key, e.g., `"general-llm"`)
- `model_id`: `string` (Actual provider string, e.g., `"gemini-2.5-flash"`)
- `verification_status`: `string` (`"verified"` | `"unverified"` | `"stale"`)
- `confidence_level`: `string` (`"high"` | `"medium"` | `"low"`)
- `stale_after_days`: `integer` (Duration in days before metadata is treated as stale)
- `last_checked_at`: `timestamptz` (Date the provider credentials were last verified)
- `created_at`: `timestamptz` (Default: `now()`)

## 4. Access Control Boundaries

> [!WARNING]
> **Data Exposure Guardrails**:
>
> - **No Direct Client Queries**: Client components must never run direct Supabase calls to load data from `prompt_analyses`.
> - **Cookie Owner Checks**: The private route `/result/[id]` is resolved exclusively by a Next.js Server Component. The component extracts the `owner_anonymous_id` from the secure cookie and queries Supabase. If the UUID does not match the database record, the server returns a `403 Forbidden` response.
> - **Token Sharing**: The route `/share/[token]` resolves records only using the `share_token` field and verifies that `is_share_enabled = true`. It returns `404 Not Found` if sharing is disabled or the token does not match, completely hiding the record's UUID and private metadata.
