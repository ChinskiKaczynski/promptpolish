# Release Notes — PromptPolish v1.0 (Release Candidate)

**Date:** 2026-06-04  
**Author:** Senior SaaS Release Engineer & Operations Lead  
**Version:** v1.0-RC  
**Status:** **Frozen (Release Candidate / Documentation Package Completed)**

---

## 1. Release Status & Verdicts

This release candidate establishes the baseline feature set for the PromptPolish v1.0 platform. The release is divided into progressive readiness milestones:

*   **Anonymous / Private Beta:** **🟢 GO**
    *   Core prompt auditing, authentication, history dashboard, and local text/markdown exporters are operationally ready, contingent on successful manual post-deployment smoke tests.
*   **Stripe Test-Mode Paid Beta (Staging): **🟢 GO (Non-Production Verification Only)**
    *   Stripe sandbox configurations, webhook event dispatching, Customer Portal redirections, and Pro tier gating logic are fully verified for non-production staging environments.
*   **Paid Production:** **🔴 NO-GO (BLOCKED)**
    *   Production billing checkouts are strictly disabled by default (`STRIPE_ENABLED=false` configuration preset). Live commercial payments and public paid launches remain blocked until all corporate entity registrations, legal reviews, EU tax structures, and vendor Data Processing Addendums (DPAs) are resolved and signed off.

---

## 2. What Is Included in v1.0

The v1.0 release packages the following features and operational components:

*   **Anonymous-First Prompt Audit Flow:** Dynamic PL/EN localization, structured scorecards, performance criteria grids, and copy-ready suggestions.
*   **Supabase Auth Integration:** User sign-up, verification triggers, secure logins, and logout workflows.
*   **Account History Dashboard:** Logged-in prompt history tracking, favorites filtering, and cascading soft-delete routes.
*   **Private Results (`/result/[id]`):** Strict cookie/owner checks enforcing page privacy.
*   **Public Share Routing (`/share/[token]`):** User-controlled sharing with clean, read-only layouts and instant 404 revocation.
*   **Multi-Format Exporters:** Markdown (`.md`) and Plain Text (`.txt`) report generation for report owners.
*   **Pro-Only PDF Export:** Server-side gate restricting PDF generation to verified Pro users.
*   **Server-Side Plan Entitlements:** Tier-gates validated directly on API routes (usage limits and premium exports) to prevent client-side bypass.
*   **Stripe Billing Foundation:** Local/staging checkout generation, customer portal links, and status synchronization logic.
*   **Stripe Webhook Foundation:** Secure buffering and syncing for key webhook events:
    *   `checkout.session.completed`
    *   `customer.subscription.created`
    *   `customer.subscription.updated`
*   **Legal Draft Banners:** Public `/terms` and `/privacy` pages populated with policy drafts and amber warnings.
*   **Launch & Operations Documentation:** Executable checklists, smoke test specifications, and operations procedures.

## 3. What Is Not Included in v1.0

The following features and compliance elements are out-of-scope for the v1.0 release:

*   **Public Paid Production Launch:** Live checkout operations remain disabled.
*   **Finalized Legal Entity details:** Registered business entity name and corporate physical addresses.
*   **Finalized Support & Privacy Inboxes:** Live operational mailboxes.
*   **Finalized Refund/Cancellation Policy:** Legal review of consumption thresholds.
*   **VAT / OSS / Stripe Tax Live Setup:** Live configuration for destination-based European tax calculation and B2B reverse charges.
*   **Multi-User / Team Accounts:** Workspace sharing, user invitations, and corporate billing structures.
*   **Enterprise Features:** SAML/SSO authentication.
*   **Billing Frequency Variations:** Yearly subscription tiers.
*   **Batch Operations:** Simultaneous multi-prompt bulk analyses.
*   **Public API & Integrations:** Browser extensions, IDE integrations, and developer API keys.
*   **Prompt Marketplace:** Public discovery feeds or shared prompt templates.

## 4. Known Limitations

Users and operators should be aware of the following system limitations:

*   **Policy Draft Status:** All terms, privacy, and billing documents are non-binding drafts. Legal compliance is not guaranteed until formal counsel sign-off.
*   **AI Engine Accuracy:** Analysis suggestions and scores are generated by the configured AI model provider. Outputs are not guaranteed to be free of hallucinations, legally reliable, or perfectly accurate. Users must verify recommendations before use.
*   **Input Privacy Warning:** Users must not input passwords, keys, or sensitive credentials. The system scans for fake secrets but cannot guarantee interception of all sensitive formats.
*   **Anonymous Session Volatility:** Anonymous audit results are linked to browser-based ownership cookies (`owner_anonymous_id`). Clearing browser caches or using incognito windows will cause users to lose access to their history.
*   **Opt-In Sharing Ownership:** Public share links (`/share/[token]`) expose read-only scorecards. Users should exercise caution when sharing sensitive or proprietary prompt content publicly.
*   **Provider Dependencies:** System latency and analysis availability are subject to the performance, rate limits, and uptime of the OpenRouter API gateway.

---

## 5. Security & Safety Notes

*   **Sensitive Data Scans:** A client-side regex engine intercepts potential secrets (database strings, payment keys) before they reach the backend or the AI provider.
*   **Access Control Gating:** Access checks are performed on the server. The `/api/export/[id]` endpoint explicitly verifies that the requester's anonymous cookie or authenticated user ID matches the document owner.
*   **PII Sanitization:** The `/admin/metrics` endpoint filters emails and hashes IP addresses to prevent telemetry logs or metrics dashboards from exposing personally identifiable information.
*   **Entitlement Enforcement:** Gated actions like PDF generation verify subscription state in the database, checking the Stripe plan mapping before processing requests.

---

## 6. Upgrade & Rollback Policies

*   **Stripe Sandbox Mode:** Staging environments can run with `STRIPE_ENABLED=true` pointing to test keys to verify checkout and customer portal workflows.
*   **Production Safety Defaults:** Production environments default to `STRIPE_ENABLED=false` to prevent accidental billing operations.
*   **Rollback Procedure:** Paid rollout features can be immediately halted by toggling `STRIPE_ENABLED=false` in environment configurations and redeploying.
*   **Approval Gate:** Upgrading to live billing requires explicit business, tax, and legal counsel sign-off.
