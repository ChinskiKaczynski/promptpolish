# PromptPolish v1.1 — Account History & Entitlement Documentation

This document describes the architectural changes, security boundaries, dynamic routing updates, and premium entitlement designs implemented for PromptPolish v1.1.

---

## 1. What was Enabled

1. **Secure Dual-Ownership History**:
   * Standardized private audit query and mutation authorization processes under `getPromptAnalysisForOwner(id, ownerAnonymousId, userId)`.
   * Enforced strict TypeScript-level authorization boundaries in backend query functions to prevent cross-user prompt leakage on shared-browser/shared-cookie sessions.
   * Unified all `softDeleteAnalysis` and `toggleFavoriteAnalysis` database updates behind ownership checking first.
   * Linked anonymous audits to newly created/authenticated accounts transparently.

2. **Server-Side Entitlement Resolution**:
   * Introduced a centralized plan configuration system inside `lib/plans/config.ts` supporting three core profiles: `'anonymous'`, `'free'`, and `'pro'`.
   * Dynamic loading of anonymous limits from `process.env.ANONYMOUS_DAILY_LIMIT`.
   * Wired dynamic resolver `getPlanSlugForUser` in `/api/analyze` to automatically govern characters limit and monthly quotas.

20. **Guarded Premium Export Actions**:
   * Wired "Eksportuj Markdown" (Markdown) and "Eksportuj TXT" (Plain Text) buttons into the private view of the prompt result screen.
   * Served these actions via dynamic routing at `/api/export/[id]?format=markdown|txt`.
   * **Authorized Owners** trigger direct server-side Markdown / Plain TXT generation.

4. **Next.js Dynamic Compilation Compliance**:
   * Declared `export const dynamic = 'force-dynamic'` across all cookie-dependent route handlers, aligning with Next.js Turbopack compiler best practices.

---

## 2. What Remains Disabled

* **Real Stripe Payments**: No real credit card or Stripe checkouts will execute until v1.2. The checkout and portal flows remain securely simulation-based.
* **Direct Client Database Access**: Clients are strictly prohibited from directly querying the Supabase database. All operations continue to run server-side via our highly restricted service role admin client.

---

## 3. How Pro Simulation Works

To facilitate seamless private testing of premium features (increased prompt length, batch audits), we have created a safe simulated upgrade/downgrade toggle in `/pricing` linked to the `/api/entitlements/simulate-pro` route.

### Production Guardrails:
* **Development**: Automatically enabled for all local developers working on `localhost`.
* **Production**: Upgrades will be strictly blocked with a `403 Forbidden` response unless the user's email address is listed inside the `ADMIN_EMAILS` environment variable.

---

## 4. How to Test Auth, History, & Entitlements

### Unit and Mock Testing:
We have updated the entire suite of backend, query, billing, and export tests. You can run them locally using:
```bash
pnpm test
```

### Manual Acceptance Flow:
1. Start the local server: `npm run dev`
2. Open PromptPolish as a Guest/Anonymous user and run a quick audit.
3. Observe that "Eksportuj Markdown" and "Eksportuj TXT" buttons are present in your result screen.
4. Go to `/login` and create a free account.
5. Visit `/account` and notice that the anonymous audit you performed in step 2 was securely linked and is now visible under **"Twoja Historia Audytów"**.
6. Visit `/pricing` and click **"Aktywuj Symulację Pro (Wersja Demo)"**.
7. Return to the audit result page. Click "Eksportuj Markdown" or "Eksportuj TXT" — they will download the clean documents.
